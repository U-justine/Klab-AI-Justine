# 🚀 How to Use This Repository

If you want to explore or run my code locally:

### 1. Clone the repository

```bash
git clone https://github.com/U-justine/Klab-AI-Justine.git
```

### 2. Enter the project

```bash
cd Klab-AI-Justine
```

### 3. Create a virtual environment

Windows:

```powershell
python -m venv .klab
```

### 4. Activate the environment

```powershell
.\.klab\Scripts\Activate.ps1
```

If PowerShell blocks activation:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Then:

```powershell
.\.klab\Scripts\Activate.ps1
```

### 5. Install dependencies

```powershell
pip install -r requirements.txt
```

### 6. Open the project

You can use **VS Code** or **Jupyter Notebook**.

```powershell
jupyter notebook
```

Select the `.klab` environment as your notebook kernel.

# 📓 Running the Assignments

Assignments are stored in:

```text
Assignments/
```

Open the relevant `.ipynb` file in VS Code or Jupyter.

Before running an assignment:

1. Activate the virtual environment.
2. Install the requirements.
3. Select the correct Python kernel.
4. Check that required datasets are available.
5. Run the notebook from the first cell to the last cell.

For reproducibility, I recommend:

**Kernel → Restart → Run All**

This ensures that the notebook does not depend on variables created during previous runs.

# 📝 Commit Convention

I use meaningful commit messages so that anyone exploring the repository can understand what changed.

### Format

```text
type: short description
```

### Examples

```text
feat: add day 2 python learning
feat: add assignment 2 data wrangling
fix: correct missing value handling
docs: update README
refactor: improve data preprocessing
data: add processed dataset
plot: add exploratory analysis charts
```

### Common commit types

| Type       | Purpose                      |
| ---------- | ---------------------------- |
| `feat`     | New feature or learning work |
| `fix`      | Bug or error correction      |
| `docs`     | Documentation changes        |
| `data`     | Dataset-related changes      |
| `plot`     | Visualization changes        |
| `refactor` | Code improvement             |
| `chore`    | Project maintenance          |

This makes the repository history easier to understand and follow.
